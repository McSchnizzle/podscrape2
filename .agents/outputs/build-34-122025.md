## Technical Details

### Root Cause Analysis
The bug was caused by React's asynchronous state updates combined with JavaScript closures:

1. User selects a status from dropdown, triggering `handleFilterChange`
2. `handleFilterChange` calls `setFilters(prev => ({ ...prev, status: value }))`
3. React batches this state update (it doesn't happen synchronously)
4. User clicks "Apply" button, triggering `applyFilters`
5. `applyFilters` reads `filters` from its closure - which was captured when the component rendered
6. Since the state update from step 2 hasn't been applied yet, `filters` contains stale values

### Solution
The fix uses a `useRef` to maintain a mutable reference to the current filter values:

1. `filtersRef` is created and initialized with `filters`
2. A `useEffect` syncs `filtersRef.current` whenever `filters` state changes
3. `applyFilters` reads from `filtersRef.current` instead of `filters`

This works because:
- `useRef` returns a mutable object that persists across renders
- `useEffect` runs after state updates are applied
- Reading `filtersRef.current` always gives the latest committed filter values

### Alternative Approaches Considered
1. **Pass filters directly to applyFilters**: Would require changing the onClick handler
2. **Use flushSync**: Would force synchronous updates but hurt performance
3. **Move to URL-driven state**: Would require larger refactor

The useRef pattern was chosen as it's idiomatic React and minimally invasive.
