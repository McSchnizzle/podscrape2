## Implementation Details

### Two-Phase Query Approach
The implementation follows the pattern established in `web_ui_hosted/app/api/story-arcs/arcs/route.ts` for Supabase OR queries, and the existing feed lookup pattern in `supabase.ts` lines 754-770.

**Query Flow**:
1. When `q` parameter is provided, first query `feeds` table for matching titles
2. If matching feeds found, build OR condition: `title.ilike.%q%,feed_id.in.(1,2,3)`
3. If no matching feeds, fall back to simple episode title search
4. Execute episode query with pagination and other filters

**Edge Cases Handled**:
- Empty search term: No search applied (existing behavior)
- No matching feeds: Falls back to episode title only (avoids empty `in()` SQL error)
- Feed search error: Silently ignores feed results, proceeds with episode title only

let matchingFeedIds: number[] = []

    .from('feeds')

  }

// Apply text search on episode title and feed title (two-phase query)
if (q) {
  if (matchingFeedIds.length > 0) {
    // Search both episode title AND feed_id
    query = query.or(`title.ilike.%${q}%,feed_id.in.(${matchingFeedIds.join(',')})`)

    // No matching feeds, just search episode title

  }
}
